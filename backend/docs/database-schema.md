
# Database Schema

This document outlines the database schemas used in the AI Blog Platform backend, based on the Mongoose models.

## 1. User Schema

The `User` schema represents a user account on the platform.

- **Collection Name:** `users`
- **Fields:**
  - `_id`: `ObjectId` (auto-generated by MongoDB)
  - `name`: `String` - The user's display name.
  - `email`: `String`, `unique: true` - The user's email address, must be unique.
  - `password`: `String` - Hashed password for local authentication.
  - `blogs`: `Array` of `ObjectId`, `ref: 'Blog'` - An array of `Blog` IDs created by this user.
  - `verify`: `Boolean`, `default: false` - Indicates if the user's email has been verified. (Note: Controller uses `isVerify`).
  - `googleAuth`: `Boolean`, `default: false` - Indicates if the user registered via Google.
  - `resetPasswordToken`: `String` - Token used for password reset (hashed).
  - `resetPasswordExpire`: `Date` - Expiration date for the `resetPasswordToken`.
  - `createdAt`: `Date` (timestamp)
  - `updatedAt`: `Date` (timestamp)

## 2. Blog Schema

The `Blog` schema represents a single blog post.

- **Collection Name:** `blogs`
- **Fields:**
  - `_id`: `ObjectId` (auto-generated by MongoDB)
  - `title`: `String`, `trim: true`, `required: true` - The title of the blog post.
  - `description`: `String`, `required: true` - A short description or summary of the blog.
  - `content`: `Object`, `required: true` - The rich text content of the blog, typically stored as a JSON object (e.g., from EditorJS).
  - `blogId`: `String`, `required: true`, `unique: true` - A unique slug-like ID for the blog post (e.g., `my-blog-title-randomid`).
  - `image`: `String`, `required: true` - URL of the featured image (from Cloudinary).
  - `imageId`: `String`, `required: true` - Public ID of the image on Cloudinary.
  - `draft`: `Boolean`, `default: false` - Indicates if the blog post is a draft (`true`) or published (`false`).
  - `creator`: `ObjectId`, `ref: 'User'`, `required: true` - The ID of the user who created this blog post.
  - `likes`: `Array` of `ObjectId`, `ref: 'User'` - An array of `User` IDs who liked this blog post.
  - `comments`: `Array` of `ObjectId`, `ref: 'Comment'` - An array of `Comment` IDs associated with this blog post.
  - `createdAt`: `Date` (timestamp)
  - `updatedAt`: `Date` (timestamp)

## 3. Comment Schema

The `Comment` schema represents a user's comment on a blog post.

- **Collection Name:** `comments`
- **Fields:**
  - `_id`: `ObjectId` (auto-generated by MongoDB)
  - `comment`: `String`, `required: true` - The text content of the comment.
  - `blog`: `ObjectId`, `ref: 'Blog'` - The ID of the blog post to which this comment belongs.
  - `user`: `ObjectId`, `ref: 'User'` - The ID of the user who posted this comment.
  - `likes`: `Array` of `ObjectId`, `ref: 'User'` - An array of `User` IDs who liked this comment.
  - `createdAt`: `Date` (timestamp)
  - `updatedAt`: `Date` (timestamp)

## 4. Like Schema (Deprecated/Not Fully Utilized)

The `Like` schema is defined but the `Blog` and `Comment` schemas directly manage likes via an array of User IDs. This schema might be a remnant or intended for a different liking mechanism.

- **Collection Name:** `likes`
- **Fields:**
  - `_id`: `ObjectId` (auto-generated by MongoDB)
  - `blog`: `ObjectId`, `ref: 'Blog'` - The ID of the blog post that was liked.
  - `user`: `ObjectId`, `ref: 'User'` - The ID of the user who liked the blog post.
  - `createdAt`: `Date` (timestamp)
  - `updatedAt`: `Date` (timestamp)
